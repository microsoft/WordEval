Looking the same is not enough. Whether an edit worked depends on what Word recognizes.
Imagine asking AI agents to edit your Word documents. Agents have begun to work inside Microsoft Word: they open the file, make the edit, and save it. Here, two agents are asked to turn two items into a numbered list. Both results look the same. Now add one item in the middle. In the left list, the new item gets no number, and the old numbers stay fixed. In the right list, Word numbers it and updates the rest. Where does this difference come from? The first agent typed the numbers as characters, so Word sees ordinary paragraphs. The second created a real Word list. So looking the same does not show that an edit worked. Do AI agents actually produce the effect we ask for, in a form Word recognizes?
Real example

Both pages show bullets. Word reads no list.

Each “•” is a typed character, so ListString is empty. Line spacing matches, the list does not, so the task fails.
Operation fidelity: the requested effect, realized as a Word state change with the correct target, attribute, and parameters.

Here is a real case. The agent was asked to add solid circle bullets to all paragraphs and set one point five line spacing. Its saved output and the reference look identical. WordEval opens both files in Word and reads the properties the request names. The agent typed a bullet character before each line, so Word sees plain paragraphs, not a list. Line spacing matches; the list does not. So the task fails. This is what WordEval measures: operation fidelity.

The checker compares the requested change and what must stay the same with expected values from the reference document, the input document, or case metadata. Across the 546 single-edit tasks it reads 139 object properties on 65 runtime objects, such as Shape.Rotation or Font.Bold.

More generally, here is how WordEval works. An agent receives a Word document and a request, and edits it with its own tools. We judge only the saved document; a missing or invalid file fails right away. The checker compares requested changes and preserved parts with expected values from a reference document, the input, or task metadata. The reference is made directly in Word, and the agent never sees it. A task passes only when all required checks pass.
Benchmark

The task landscape

Atomic: one edit per task · Compositional: several linked edits in one document

642editing tasks546 Atomic · 96 Compositional
15Word feature areas231 Word commands
319atomic intentseach linked to an Atomic task
WordEval contains six hundred forty-two tasks covering fifteen Word feature areas, including text, lists, tables, charts, and shapes. Atomic tasks test one edit. Compositional tasks combine linked edits in one document, asking whether edits that work alone still work together. Each combined edit links to a single-edit task using the same command, helping us investigate failures when edits share a document.

We evaluated eight AI systems. Claude Code with Opus five achieved the highest overall pass rate, eighty-seven point one percent. Three human participants averaged eighty-two point eight percent. The other seven AI systems scored between forty-four point five and sixty-six point seven percent. Every system scored lower on combined-edit tasks than on single edits. The gaps ranged from three point two to nineteen point one percentage points.
A closer look

Rotate, then align

Rotation and sizes match. A 60 × 120 pt rectangle turned 90° is 60 pt tall on the page, so its visible top edge sits 30 pt lower than the stored frame top says. The same agent passes each edit when asked for it alone.

Consider this combined request: rotate the middle rectangle ninety degrees, then align all three rectangles by their visible top edges. Opus five gets the rotation and sizes right. However, the visible top edges do not align, so the task fails. Its stored frame tops line up, but rotation shifts the visible edge relative to that frame. The same system passes each edit when requested separately.

Performance also varies across Word features. Tables and paragraphs lead, while pictures trail. Similar single-edit scores can hide very different combined-edit scores. Gemini three point eight Flash and G L M five point two both score about fifty-eight percent on single edits. Their combined-edit scores are forty-nine percent and thirty-nine point six percent. Failures include valid documents with incorrect edits, invalid documents that Word cannot open or that fail validation, and cases where no file is submitted.
Conclusion

Whether a Word edit took effect is a question of document state, not appearance alone.

WordEval makes that state the unit of evaluation. Current agents handle many single operations, but every one of them loses accuracy when edits share a document.

WordEval makes the resulting document state central to evaluation: it tests whether a request was carried out precisely, and whether edits that work alone stay reliable together. The current tests use synthetic documents and English instructions, and require Windows and Word, so scores describe performance on these controlled tasks. Thank you.
